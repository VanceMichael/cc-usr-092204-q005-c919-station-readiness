# C919新航点保障放行

本项目服务于记录 C919 航点启用所需的地面资源、人员和放行条件。仓库保存领域资料、交换契约和可运行的服务入口，把**逐航点放行**做成可计算、可解释、可回放的领域模型。

## 领域事实

- 南航 C919 航点已由四个扩展到十七个
- 广州枢纽建立飞机流、旅客流和行李流监控
- 新航点设置专属值机、航显和业务骨干保障
- 机场同时承诺专属值机、航显、廊桥、行李、机务保障，任一项临时缺位都可能使航班在旅客到场后无法按计划运行

## 放行规则（模型实现）

运行控制部门按八类条件评估每个航点：机场承诺、机型适配、航线天气、保障单位、人员资质、备件工具、廊桥兼容、演练结果。

1. **能力版本冻结**：新航季或换机计划冻结当日采用的能力版本（样例航班 CZ2381 冻结 `WCV-CKG-C919-2026Q3-001`）。当日新发布的 002 版本不自动生效。
2. **事件触发重算**：人员调班、设备故障、强对流运行限制、临时机位变化按真实发生时间重新计算可用方案（`recompute_reason` 标出最近触发事件）。
3. **缺口、替代措施与责任人**：每条缺口含冻结承诺、当前状态、最后责任人、替代措施、按冻结标准的预计恢复时刻。
4. **禁止静默降级**：已售票航班存在未决缺口时绝不自动 GO；只能 DELAY（缺口有按原标准恢复的预期）或 NOGO（仅能靠降级替代，如廊桥改远机位客梯车，须签派员显式决策）。
5. **联动复核**：人员失位连带复核备件与演练；机位变化连带复核行李与值机方案，联动项以 `LINKED_GAP` 标出。
6. **并发确认唯一结论**：机场与航司同时确认时，按 `occurred_at`（相同则按接收序号）先到生效，后到确认不覆盖。
7. **敏感维修资料岗位隔离**：非机务维修岗只能看到文档 ID 与 RESTRICTED 状态，读不到正文。
8. **断网补录保留真实时间**：异地团队补录事件以 `occurred_at` 参与时序，`recorded_at` 仅记录接收时间。
9. **三流回放**：按真实时间重放飞机流、旅客流、行李流事件和各时点评估结论。

样例决策链：05:20 人员调班 NOGO → 05:50 断网补录增援计划 DELAY → 07:20 廊桥改远机位（降级）+天气/备件未恢复 NOGO → 增援、工具、天气陆续恢复但廊桥仍为远机位，NOGO 拦截静默降级 → 11:20 廊桥修复恢复 207 机位，GO。

## 目录说明

- `contracts/`：`context.schema.json` 领域上下文、`release.schema.json` 放行结论结构约定。
- `fixtures/`：`context.json` 领域资料；`capability.json` 航点能力版本与联动规则；`operations.json` 航班、确认、维修文档与运行事件样例。
- `src/catalog.py`：领域资料读取。
- `src/release.py`：放行评估、并发裁决、岗位隔离、回放的纯领域模型。
- `src/server.py`：HTTP 服务入口。
- `tests/`：核对领域资料与全部放行规则。

## 本地检查

```bash
python3 -m unittest discover -s tests -v
```

## 服务接口

```bash
python3 -m src.server
```

- `GET /health`：健康检查
- `GET /context`：领域上下文
- `GET /release?flight=CZ2381&at=2026-09-26T10:30:00+08:00`：某时刻放行结论（缺口、替代措施、责任人、降级拦截、并发裁决）
- `GET /confirm?flight=CZ2381`：并发确认的唯一生效结论
- `GET /maintenance?doc=MRO-C919-2609-17&role=签派员`：按岗位返回维修资料（全文或受限状态）
- `GET /replay?flight=CZ2381`：飞机流/旅客流/行李流与评估结论的完整时间线
